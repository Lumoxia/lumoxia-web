# Design: Age Suitability page for The Royal Game of Ur

Implements `requirements.md` (approved; decisions D1 no rating tier on the page, D2 footer links only, D3 region section included). It adds a fourth generated page, `age`, to the existing static-site generator. No new dependency, no new mechanism.

## Approach

The site is generated by `scripts/build.py` from `templates/*.html` and `i18n/strings/<code>.json`; the generated pages are committed and CI checks they are current. The Age Suitability page is a new page of that system, modelled on `templates/support.html` (same header, language menu, `doc` article, footer):

| Piece | Change |
|---|---|
| `scripts/build.py` | Add to `PAGES`: `"age": ("age.html", "royal-game-of-ur/age-suitability/")`. `render_all`, `sitemap`, `alternates`, `langmenu`, canonical and `x-default` already loop over `PAGES`, so the 15 generated pages and the 15 sitemap entries (each with 16 alternate links) need no further code. |
| `templates/age.html` | New template (below). |
| `i18n/strings/*.json` (15 files) | New keys `meta.age.*`, `age.*`, `footer.age` (below), identical key set in every language. |
| `templates/privacy.html`, `templates/support.html`, `templates/index.html` | Add a footer link to the new page (D2: not the top navigation). |
| Generated pages | `royal-game-of-ur/age-suitability/index.html` and `<code>/royal-game-of-ur/age-suitability/index.html` for the 14 other languages; the Privacy, Support and landing pages and `sitemap.xml` regenerate. |
| `scripts/test_build.py` | New tests and the fixture-comparison adjustment (below). |
| `README.md`, `i18n/README.md` | Mention the page where pages are listed. |
| `.github/workflows/check.yml` | No change: its path filters already cover `royal-game-of-ur/**`, `*/index.html`, `templates/**`, `i18n/**`, `sitemap.xml`, `scripts/**`. |

URL: `https://lumoxia.art/royal-game-of-ur/age-suitability/` (English, the value for the App Store Connect field) and `https://lumoxia.art/<code>/royal-game-of-ur/age-suitability/` for the others. The path stays under `royal-game-of-ur/` like Privacy and Support, because the page is about the app, not the studio.

## Template: `templates/age.html`

Copy of the `support.html` skeleton with these differences:

- `<title>{{t:meta.age.title}}</title>` and `meta description` from `meta.age.description`.
- The `<article class="container doc">` body, in this order (each heading `h2`, as on the Privacy page):
  1. `h1` `{{t:age.h1}}`, `p.doc-meta` `{{t:age.meta}}`, bold summary `<strong>{{t:age.short}}</strong>`.
  2. `h2` `age.content.h`, intro `age.content.p`, then a `<ul>` of six `<li>` (`age.content.l1` to `l6`).
  3. `h2` `age.buy.h`, paragraphs `age.buy.p1` (the purchase and Apple's parental controls) and `age.buy.p2` (browser links).
  4. `h2` `age.privacy.h`, paragraph `age.privacy.p` with an inline link to `{{base}}royal-game-of-ur/privacy/`.
  5. `h2` `age.region.h`, paragraph `age.region.p` (D3).
  6. `h2` `age.changes.h`, paragraph `age.changes.p`.
  7. `h2` `age.contact.h`, paragraph `age.contact.p` with a link to `{{base}}royal-game-of-ur/support/`, then the same contact button as Support: `mailto:rgur-support@lumoxia.art?subject={{url:age.subject}}`.
- Footer: the Support footer plus the new link `<a href="{{base}}royal-game-of-ur/age-suitability/">{{t:footer.age}}</a>` between Support and the email address.
- Top navigation is unchanged (D2).

No new CSS: `doc`, `doc-meta`, `doc-contact`, `btn` and RTL rules already exist. No JavaScript, cookies or external requests beyond the fonts the other pages already load.

The footer link is added the same way in `privacy.html` and `support.html` (same `&middot;` separator pattern) and in `index.html`'s footer link row after Patreon, so all four page types link to it (requirement 3.1).

## Translations

The 14 other files get translations of the strings above, drafted with AI assistance exactly as the existing pages were. Rules to follow, all enforced by `check_i18n.py`: same keys everywhere, same tags and tokens as English, no em or en dashes. The `_review` field stays `unreviewed`. The Japanese and Korean app terms are the hand-drafted entries already in `app-terms.json`. Arabic and Hebrew render through the existing RTL handling (`dir`, font set); `<bdi dir="ltr">` wraps the e-mail address as on the other pages. The longest languages (German, French, Russian, Tagalog) are checked for how the contact button and the six-item list wrap, as `i18n/README.md` already asks of reviewers.

## Tests (`scripts/test_build.py`)

1. `PAGES` in the test file gets `"age": "age.html"`, and the all-pages loops (generated in every language, `lang` and `dir`, canonical, `hreflang` including `x-default`, language menu with 15 entries and the current one marked, relative links resolve) include it through the existing loops.
2. New `test_age_page_states_the_content_facts`: for every language the generated page contains the six `age.content.l*` strings, `age.buy.p1`, `age.privacy.p`, `age.region.p` and `age.changes.p` rendered, and the mailto subject equals the URL-encoded `age.subject`. For languages other than English, those strings must differ from the English text, so an untranslated copy fails.
3. New `test_age_page_does_not_state_a_rating`: no generated age page contains a pattern like `4+`, `9+`, `13+`, `16+`, `18+` (D1), except the Australian "16" inside `age.region.p` which is written as a number without a plus sign.
4. New `test_age_page_is_linked`: every Privacy, Support, landing and Age page, in every language, has a footer link whose `href` ends in `royal-game-of-ur/age-suitability/`; the top navigation of every page has no such link (D2).
5. New `test_sitemap_has_the_age_pages`: 15 `<loc>` entries for the age page, each listing 15 alternates plus `x-default`.
6. `test_english_text_unchanged` compares the English Privacy, Support and landing text with the pre-change fixtures in `scripts/fixtures/english-before/`. The new footer link adds text to all three, so, like the existing Patreon footer addition, the test strips `footer.age` and its preceding `&middot;` separator before comparing. The fixtures themselves are not changed.
7. `python3 scripts/check_i18n.py`, `python3 scripts/build.py --check` and `python3 scripts/test_build.py` all pass, which is what CI runs.

## Verification outside the tests

- Serve locally (`python3 -m http.server 8080 --bind 127.0.0.1 --directory .`) and view the English, Arabic, German and Japanese pages in a browser at desktop and phone widths, checking the layout against the Support page, RTL direction in Arabic and Hebrew, and that the footer link opens the page.
- The English URL is the value to paste into App Store Connect: App Information, Age Rating, Age Suitability URL (Optional). Nothing in the repository can enter it; it is a manual step for the owner at submission, and the field's format rules are confirmed on the live form then.

## Alternatives considered

- **Hand-written static HTML.** Rejected: the README forbids editing generated pages, and the other pages are all generated; it would skip translation checking.
- **One page for all languages with a language switch in JavaScript.** Rejected: the site's convention is one pre-generated page per language, which also gives each language its own indexable URL and `hreflang` entry.
- **Extending the Privacy page with an "Age" section instead of a new page.** Rejected: Apple's field wants a dedicated page that appears on the product page, and requirements ask for its own URL.
- **Stating the age tier on the page (D1 option B).** Rejected by D1.

## Risks

- Translation quality is unreviewed, as for all existing pages. The page's claims are plain facts, which limits the risk.
- The page makes factual claims about the app (for example "no way to contact other players"). They match the Privacy page and the app today; they are pinned in the requirements (4.3) to be updated before any app change ships.
